Projet fil rouge — mise en place

Premier chapitre « pratique » du fil rouge. On cadre l'API Fioul Groupé, on ajoute les dépendances utiles, un premier test d'intégration, et Swagger pour explorer l'API.

1 · L'API cible 2 · Dépendances 3 · Premier test 4 · Swagger
1 Cadrage

L'API Fioul Groupé

On vise une API REST au-dessus de la base MongoDB, avec le CRUD des campagnes et l'inscription des particuliers.

GET    /api/campagnes            // lister (filtre ?zone=)
GET    /api/campagnes/{id}       // détail (volume + prix calculés)
POST   /api/campagnes            // ouvrir            [COORDINATEUR]
POST   /api/campagnes/{id}/commandes  // rejoindre    [PARTICULIER]
PUT    /api/campagnes/{id}/cloturer   // clôturer    [COORDINATEUR]
2 Étape

Les dépendances du projet

On ajoute au pom.xml : Spring Web, Spring Data MongoDB, Validation, et springdoc-openapi (Swagger). Plus tard : Spring Security (chapitre 12).

Mises à jour — on part sur des versions à jour du spring-boot-starter-parent pour écarter d'éventuelles dépendances vulnérables (bon réflexe, à relier au cours Cyber).
3 Étape

Le test de contexte

Spring Boot génère un premier test qui vérifie que le contexte démarre. C'est le socle des tests d'intégration.

@SpringBootTest
class FioulApiApplicationTests {
    @Test void contextLoads() { }
}
4 Étape

Swagger UI pour explorer

La dépendance springdoc-openapi déploie sans configuration une interface de test.

Swagger UI : http://localhost:8080/swagger-ui/index.html OpenAPI : http://localhost:8080/v3/api-docs
🛢️ Sur le projet Fioul Groupé

Cadre l'API dans une issue GitHub, ajoute les dépendances, vérifie le test de contexte au vert et Swagger accessible. Le projet est prêt à recevoir ses couches (Web, Services, Data) dans les chapitres suivants.

À retenir
  • On définit d'abord les endpoints cibles.
  • Dépendances : Web, Data MongoDB, Validation, springdoc.
  • @SpringBootTest = test d'intégration ; Swagger pour explorer.

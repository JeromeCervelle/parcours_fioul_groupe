Projet — la couche Data

On branche l'API sur la vraie base MongoDB : entités, repositories, connexion, et données de départ. L'API n'utilise plus de données factices.

1 · Les entités2 · La connexion3 · Brancher le service4 · Données de départ
1 Étape

Entités & sous-documents

On finalise Campagne (avec List<Commande> embarquée), Commande, et Fournisseur (avec ses Palier). Les types monétaires en BigDecimal (cf. Mongo ch. 16).

public class Commande {
    private int litres;
    private String commune;
    private String adresse;
}
2 Étape

La connexion à MongoDB

On configure l'URI (locale en dev, Atlas en prod via secret).

spring.data.mongodb.uri=mongodb://localhost:27017/fioul   # dev
# prod : spring.data.mongodb.uri=${MONGODB_URI}
3 Étape

Brancher le service sur le repository

Le service utilise désormais repo.findAll(), repo.save()… Les données factices disparaissent ; l'API lit et écrit dans MongoDB.

Vérifier — insère une campagne via POST /api/campagnes, relis-la dans Compass : elle doit apparaître dans la collection campagnes.
4 Pratique

Un jeu de données de départ

On peut initialiser des fournisseurs et quelques campagnes au démarrage (un CommandLineRunner), pour tester tout de suite.

🛢️ Sur le projet Fioul Groupé

Connecte l'API à ta base fioul, insère 2-3 fournisseurs (avec paliers) et vérifie de bout en bout : POST une campagne, ajoute des commandes, consulte le détail — le volumeTotal et le prixLitre doivent se calculer.

À retenir
  • Entités finalisées, monétaire en BigDecimal.
  • Connexion via spring.data.mongodb.uri (secret en prod).
  • Service branché sur le vrai repository ; jeu de données de départ.

Projet — packaging & déploiement

On met réellement l'API Fioul Groupé en ligne, avec Docker, la base sur Atlas, et un déploiement déclenché par la forge (CI/CD).

1 · Build de prod2 · Base Atlas3 · Lancer en ligne4 · CI/CD
1 Étape

Le build de production

On construit l'image Docker du projet à partir du Dockerfile du chapitre 14, taguée par version.

docker build -t fioul-api:1.0.0 .
docker run -p 8080:8080 \
  -e SPRING_PROFILES_ACTIVE=prod \
  -e MONGODB_URI="$MONGODB_URI" fioul-api:1.0.0
2 Étape

La base sur Atlas

On pointe l'API vers le cluster Atlas (parcours MongoDB, chapitre 17) : utilisateur applicatif, IP autorisée pour l'hébergeur, URI en secret.

3 Étape

Mettre en ligne

On pousse l'image sur une plateforme (Railway, Render, un VPS…). L'API obtient une URL publique (HTTPS) que l'appli Flutter utilisera comme apiBaseUrl.

HTTPS — en production, l'API doit être servie en HTTPS (certificat), surtout parce qu'elle transporte des JWT.
4 Pratique

Automatiser (CI/CD)

On complète le workflow GitHub Actions : à chaque tag v*, construire l'image et la déployer. Le déploiement devient reproductible et tracé.

🛢️ Sur le projet Fioul Groupé

Déploie fioul-api connectée à Atlas, récupère son URL HTTPS et note-la dans le README. Ajoute une release v1.0.0 (parcours Forge, séance 7). L'API est en ligne : le parcours Flutter peut la consommer.

À retenir
  • Image Docker taguée par version ; config par variables d'env.
  • Base sur Atlas ; URL API publique en HTTPS.
  • Déploiement automatisé via la CI/CD de la forge.

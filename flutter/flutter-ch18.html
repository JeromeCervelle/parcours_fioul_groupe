Chapitre 18 / 19

Publication d'une application

Préparer et générer une version distribuable : icône, écran de démarrage, signature, et le format attendu par le Play Store.

1 · Finitions2 · Signer3 · Build release4 · Le Store
1 Étape

Icône & écran de démarrage

On personnalise l'icône (paquet flutter_launcher_icons) et l'écran de démarrage (flutter_native_splash), on fixe le nom et la version dans pubspec.yaml.

2 Étape

Signer l'application

Android exige une signature : on génère un keystore et on configure la signature de release. Le keystore est un secret précieux (à ne jamais committer).

3 Étape

Générer la version release

Pour le Play Store, on produit un App Bundle (.aab) ; pour un test direct, un APK.

flutter build appbundle --release   # pour le Play Store
flutter build apk --release         # pour installer directement
4 Notion

Le dépôt sur le Store

Sur la Play Console : fiche de l'app (description, captures), politique de confidentialité, puis test interne avant production. (iOS : App Store Connect, compte payant.)

🛢️ Sur le projet Fioul Groupé

Pour l'évaluation, un APK release suffit : génère-le, attache-le à la release GitHub v1.0.0 (parcours Forge, séance 7). Une vraie publication Play Store est une ouverture facultative.

À retenir
  • Finitions : icône, splash, nom, version.
  • Signature obligatoire (keystore secret).
  • build appbundle (Store) / build apk (direct) ; Play Console.

Présentation d'Atlas

Jusqu'ici, MongoDB tournait en local. Atlas est le service géré (cloud) de MongoDB : on y héberge sa base, accessible depuis Internet — ce qui permettra à l'API Spring et à l'appli Flutter de s'y connecter, où qu'elles s'exécutent.

1 Notion

Un DBaaS : la base en tant que service

Atlas est un DBaaS (Database as a Service) : MongoDB installe, sauvegarde, met à jour et surveille la base pour toi, sur le cloud de ton choix (AWS, Azure, GCP). Il existe un palier gratuit (M0), parfait pour un projet pédagogique.

2 Étape

Créer un cluster gratuit

Les grandes étapes, depuis cloud.mongodb.com :

  • Créer un compte, puis un projet.
  • Déployer un cluster M0 (Free), choisir une région proche (ex. Paris).
  • Attendre quelques minutes le provisionnement.
Vocabulaire — un cluster est le groupe de serveurs qui héberge la base (répliquée pour la disponibilité). En M0, tout cela est transparent.
3 Étape

Accès & sécurité

Deux réglages indispensables avant de se connecter :

  • Database Access — créer un utilisateur (login + mot de passe) avec ses droits.
  • Network Access — autoriser les adresses IP qui peuvent se connecter (liste blanche d'IP).
Bonne pratique (lien Cyber) — n'autorise que les IP nécessaires (pas 0.0.0.0/0 en production), utilise un mot de passe fort, et ne mets jamais l'URI de connexion (qui contient le mot de passe) dans le dépôt Git : passe par un secret / variable d'environnement.
4 Étape

Se connecter à Atlas

Atlas fournit une URI de connexion (format mongodb+srv://) à utiliser avec mongosh, Compass ou un driver.

# avec mongosh
mongosh "mongodb+srv://user:motdepasse@cluster0.xxxx.mongodb.net/fioul"
# côté Spring (application.properties), via une variable d'environnement
spring.data.mongodb.uri=${MONGODB_URI}
5 Notion

Les outils intégrés

Atlas ne fait pas qu'héberger ; il offre :

  • Data Explorer — parcourir et éditer les documents dans le navigateur.
  • Sauvegardes automatiques et restauration.
  • Metrics — surveiller performances et requêtes lentes.
  • Atlas Search (recherche avancée, cf. chapitre 12) et bien d'autres.

Bilan du parcours MongoDB

🛢️ Sur le projet Fioul Groupé

Héberge ta base fioul sur un cluster M0, crée un utilisateur applicatif et autorise l'IP de développement. Récupère l'URI et garde-la dans un secret (pas dans Git). À partir de là, l'API Spring (parcours 2) se connectera à cette base, et l'appli Flutter (parcours 3) l'atteindra via l'API — le fil rouge est prêt à devenir une vraie application en ligne.

🎉 Parcours MongoDB terminé

Tu as parcouru les 17 chapitres : du modèle documents jusqu'aux agrégations, aux index, à la géolocalisation et à l'hébergement. Tu as toutes les briques pour modéliser et alimenter la base du projet. Étape suivante : exposer ces données via une API avec le parcours Spring Boot, ou t'entraîner sur le guide pas à pas.

Ce qu'il faut retenir du chapitre
  • Atlas = MongoDB hébergé et géré (DBaaS), avec un palier gratuit M0.
  • Avant de se connecter : créer un utilisateur (Database Access) + autoriser les IP (Network Access).
  • URI mongodb+srv://… ; jamais de mot de passe dans Git (secret / variable d'env).
